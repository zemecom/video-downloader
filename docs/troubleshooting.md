# Решение частых проблем (Troubleshooting)

В данном разделе собраны наиболее частые проблемы, возникающие при локальном запуске и интеграции утилиты, а также способы их решения.

---

## 1. Проблемы с бинарными зависимостями

### Ошибка: `yt-dlp: command not found` или `ffmpeg: command not found`

CLI-утилита использует системные вызовы для работы с этими программами.

**Решение:**

- Установи их через пакетный менеджер (Homebrew на macOS, apt на Debian/Ubuntu):

  ```bash
  brew install yt-dlp ffmpeg
  ```

- Убедись, что пути к бинарникам прописаны в системной переменной `$PATH`. Ты можешь проверить это с помощью команды `make doctor`.

### Ошибка скачивания: `Signatures are invalid / Video unavailable`

Если скачивание видео внезапно перестает работать (особенно с YouTube), скорее всего, изменились внутренние алгоритмы платформы.

**Решение:**

- `yt-dlp` регулярно обновляется для обхода этих ограничений. Обнови утилиту до последней версии:

  ```bash
  yt-dlp -U
  ```

  или через Homebrew:

  ```bash
  brew upgrade yt-dlp
  ```

## 2. Ошибки конфигурации и окружения

### Ошибка: `Environment not bootstraped / config files missing`

При первом запуске утилита выдает ошибку о нехватке `.env` или `proxy_rules.yaml`.

**Решение:**

- Создай локальные конфигурационные файлы из шаблонов:

  ```bash
  make init
  ```

- Затем обязательно заполни созданный `.env` (особенно пути к папкам загрузок) и проверь правильность синтаксиса в `proxy_rules.yaml`.

### Ошибка: `Connection timeout / Proxy unreachable`

Если трафик идет через нерабочий прокси-сервер, скрипт зависнет или выбросит исключение сети.

**Решение:**

- Проверь, какие прокси прописаны в переменных `PROXY_LOCAL` и `PROXY_REMOTE` в `.env`.
- Временно запусти загрузку в обход прокси с помощью флага `--no-proxy` (`-np`):

  ```bash
  php bin/ytd https://youtu.be/example -np
  ```

- Проверь маршрут URL с помощью `make doctor` (или `php bin/ytd --doctor`). Утилита покажет, к какой категории относится домен и какой прокси будет применен.

## 3. Проблемы с интеграцией Chrome Extension

### Ошибка: Соединение с хостом разрывается мгновенно (`disconnected`)

При попытке скачать через расширение в консоли браузера появляется ошибка `Host disconnected` или `Error write to closed pipe`.

**Решение:**

- Убедись, что в `logs/errors.log` нет фатальных синтаксических ошибок PHP. Если PHP падает с ошибкой (`Fatal Error`, `Parse Error`), он выводит текстовый стек вызовов в `stdout`, что ломает бинарный протокол Chrome.
- Проверь, установлены ли Composer-зависимости. Если скрипт запускается Chrome'ом, а `vendor/autoload.php` отсутствует, процесс завершится ошибкой.
- Попробуй перезапустить установку хоста:

  ```bash
  make chrome-ext-install
  ```

## 4. Логи и сбор информации об ошибках

Если проблему не удается решить простыми методами, изучи лог-файлы в директории `logs/` (создается автоматически в корне проекта):

- **`logs/errors.log`**: Сюда записываются все необработанные исключения PHP с детальным стеком вызовов (Stack Trace).
- **`logs/native-host.log`**: Детализация обмена JSON-пакетами между расширением Chrome и PHP-хостом.
- **`logs/native-host-jobs/`**: Логи фоновых процессов скачивания, запущенных из Chrome. По ним можно понять, почему фоновый `yt-dlp` завершился с ошибкой.
