# Разработка и тестирование

В этом разделе собрана информация для разработчиков, контрибьюторов и продвинутых пользователей.

## Полезные команды (`Makefile`)

Для автоматизации процессов разработки доступен набор make-таргетов:

- `make install-deps` — устанавливает PHP-зависимости через Composer.
- `make init` — создаёт `runtime`-конфиги из шаблонов.
- `make doctor` — проверяет окружение и локальные конфиги.
- `make doctor-smoke` — прогоняет `doctor` на шаблонных конфигах во временном runtime-root (часть локального CI).
- `make chrome-ext-paths` — показывает пути к unpacked extension и native host.
- `make chrome-ext-install` — устанавливает native host для Chrome-расширения.
- `make chrome-ext-uninstall` — удаляет manifest native host из профиля Chrome.
- `make proxy-install` — настраивает фоновый проброс портов (launchd) для обхода ограничений macOS Local Network Privacy.
- `make proxy-uninstall` — удаляет конфигурацию проброса портов.
- `make clean-logs` — удаляет все файлы логов из папки `logs/`.
- `make test` — запускает unit-тесты (PHPUnit).
- `make test-integration` — запускает integration-suite (требует настройки `.env`).
- `make lint` — запускает PHP CS Fixer и PHPStan.
- `make lint-fix` — автоматически исправляет проблемы со стилем кода (PHP CS Fixer).
- `make check` — удобный локальный минимум: сначала запускает lint, потом unit-тесты.
- `make build` — собирает готовый исполняемый файл `ytd.phar` с помощью Box.

Можно запускать эти же скрипты напрямую через Composer, если `make` недоступен:

```bash
composer test
composer test-integration
composer lint
composer lint-fix
composer check
```

> [!TIP]
> Для локальной отладки CLI используется Xdebug на порту `9003`. Текущая конфигурация рассчитана на ручной запуск по триггеру (`xdebug.start_with_request=trigger`), поэтому для отладки запускай команды так: `XDEBUG_TRIGGER=1 php bin/ytd --help`, а в PhpStorm заранее включай `Start Listening for PHP Debug Connections`.

## Integration-тесты

Сейчас integration-suite остаётся ручной и облегчённой.

Практически это значит:

- `composer test-integration` и `make test-integration` существуют как отдельный контур тестирования.
- Для реальных сетевых сценариев тебе всё равно нужно заполнить `TEST_*` переменные в `.env`.
- Часть integration-логики пока служит каркасом и не заменяет полноценные ручные прогоны на рабочей сети.

Если хочешь прогонять реальные сценарии, заполни следующие переменные в `.env`:

- `TEST_URL_DIRECT`
- `TEST_URL_REMOTE`
- `TEST_URL_LOCAL`
- `TEST_PLAYLIST_LOCAL`

## Логи и диагностика

- Команда `doctor` (флаг `--doctor`) проверяет наличие `yt-dlp`, `ffmpeg`, `.env`, `proxy_rules.yaml` и базовую корректность конфигурации маршрутизации.
- Режим `--fast` использует `ffmpeg` напрямую и может откатиться к обычной загрузке, если источник не отдаёт подходящие отдельные video/audio потоки.
- Необработанные ошибки приложения пишутся в `logs/errors.log` внутри runtime-root.
- Если задана переменная среды `YTD_ERROR_LOG_FILE`, лог можно вынести в другой путь.

## Ограничения проекта

- Проект зависит от внешних системных бинарников `yt-dlp` и `ffmpeg`.
- Опция `--fast` в первой версии работает только для одиночных видео (без `--audio`, `--manual` и playlist flow).
- Playlist flow является интерактивным и рассчитан в первую очередь на запуск в локальном терминале.
- Реальное поведение загрузки сильно зависит от доступности конкретных сайтов, текущих прокси и политики самих источников-хостингов.
- Integration-покрытие в PHP-версии пока менее развито, чем исторически было в старой Python-версии.
