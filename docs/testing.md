# Тестирование и проверка качества кода (Testing & Mutations)

В проекте настроен многоуровневый контур тестирования, гарантирующий стабильность работы CLI-приложения и интеграций.

---

## 1. Разделение тестовых контуров

Тесты разделены на две группы: быстрые Unit-тесты и сетевые Integration-тесты.

### Unit-тесты (Быстрые)

Unit-тесты проверяют чистую логику работы компонентов в изоляции (без выполнения реальных сетевых запросов и скачиваний).

- Тестируют: логику парсинга аргументов, маппинг плейлистов, валидацию конфигураций, логику разбора вывода `yt-dlp`.
- Запуск:

  ```bash
  make test
  ```

  или напрямую через PHPUnit:

  ```bash
  vendor/bin/phpunit --testsuite=Unit
  ```

### Integration-тесты (Сетевые / Тяжелые)

Проверяют реальное сетевое взаимодействие и корректность интеграции с внешними утилитами (`yt-dlp`, `ffmpeg`).

- По умолчанию эти тесты пропускаются или используют моки, если не заполнены тестовые URL в `.env` (переменные `TEST_URL_DIRECT`, `TEST_URL_LOCAL`, `TEST_URL_REMOTE`).
- Запуск:

  ```bash
  make test-integration
  ```

  или напрямую через PHPUnit:

  ```bash
  vendor/bin/phpunit --testsuite=Integration
  ```

## 2. Мутационное тестирование (Infection)

Мутационные тесты помогают оценить *качество и полноту* покрытия кода тестами. В отличие от стандартного Code Coverage (которое измеряет только то, выполнились ли строки кода во время тестов), Infection проверяет, могут ли тесты заметить баг, если он появится в коде.

### Принцип работы

1. Infection запускает твои тесты и убеждается, что они проходят.
2. Затем он делает копию твоего кода и вносит в него одну мелкую ошибку (мутацию), например:
   - Меняет оператор `<` на `<=`.
   - Меняет `true` на `false`.
   - Удаляет вызов метода.
3. Infection запускает тесты для этого мутировавшего кода:
   - Если тесты упали — мутант «убит» (**Killed**). Это хороший результат (тесты поймали баг).
   - Если тесты прошли успешно — мутант «выжил» (**Escaped**). Это означает, что тесты не проверяют это ветвление логики должным образом.

### Запуск мутационных тестов

Для запуска Infection требуется драйвер покрытия (Code Coverage) в PHP. Мы используем **PCOV** (быстрый драйвер для CLI) или **Xdebug**.

Команда запуска:

```bash
make infection
```

Результаты работы и список всех выживших мутантов записываются в лог-файл `logs/infection.log` (или выводятся в HTML-отчет, если это настроено). Стремись к показателю **Mutation Score Indicator (MSI)** выше 80%.

## 3. Проверка архитектурных слоев (Deptrac)

Помимо логических багов, в проекте отслеживаются архитектурные нарушения (например, если сервис бизнес-логики случайно импортирует класс контроллера/команды).

Проверка выполняется с помощью **Deptrac**:

```bash
make deptrac
```

Если в коде нарушены правила зависимостей, Deptrac выведет список файлов с ошибками и завершится с ненулевым кодом возврата, что заблокирует коммит или сборку в CI.
