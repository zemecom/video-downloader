# Конфигурация

Runtime-конфигурация хранится в двух файлах:

- `.env`
- `proxy_rules.yaml`

Эти файлы игнорируются Git. В репозитории лежат только шаблоны, из которых они создаются (`.env.example`, `proxy_rules.example.yaml`).

## Переменные окружения (`.env`)

- `PROXY_LOCAL` - прокси для маршрутов с типом `local` (например, `socks5://127.0.0.1:1080` или `http://...`)
- `PROXY_REMOTE` - прокси для маршрутов с типом `remote`
- `PROXY_RULES_FILE` - путь к YAML-файлу маршрутизации; относительные пути считаются от автоматически найденного runtime-root (по умолчанию: `proxy_rules.yaml`)
- `DOWNLOAD_DIR_YOUTUBE` - каталог для загрузок с YouTube
- `DOWNLOAD_DIR_GENERAL` - каталог для загрузок с прочих сайтов
- `OUTPUT_FORMAT` - итоговый контейнер для сборки видео: `mkv` или `mp4`
- `CONCURRENT_DOWNLOADS` - сколько роликов из плейлиста качать одновременно по умолчанию
- `CONCURRENT_FRAGMENTS` - сколько фрагментов одного файла качать одновременно через встроенные механизмы `yt-dlp`
- `YTD_PROGRESS_DELTA` - интервал обновления прогресса `yt-dlp` в секундах
- `YTD_PROGRESS_NEWLINE` - печатать прогресс построчно (`1`, `true`, `yes`) вместо очистки текущей строки
- `TEST_URL_DIRECT` - необязательный URL для ручного direct integration-теста
- `TEST_URL_REMOTE` - необязательный URL для ручного remote integration-теста
- `TEST_URL_LOCAL` - необязательный URL для ручного local integration-теста
- `TEST_PLAYLIST_LOCAL` - необязательный URL плейлиста для ручной проверки playlist flow через local-route
- `YTD_PROJECT_ROOT` - явный runtime-root, если нужно переопределить автоматическое определение каталога проекта
- `YTD_ERROR_LOG_FILE` - кастомный путь для лога ошибок (по умолчанию: `logs/errors.log`)
- `YTD_NATIVE_HOST_RECENT_DOWNLOADS_DB_FILE` - кастомный путь для `sqlite`-базы загрузок Native Host
- `YT_DLP_PATH` - путь к кастомному исполняемому файлу `yt-dlp` (по умолчанию системный `yt-dlp`)

## Правила маршрутизации (`proxy_rules.yaml`)

Конфигурационный файл использует три фиксированные секции:

- `direct` (прямое скачивание без прокси)
- `local` (скачивание через прокси, указанный в `PROXY_LOCAL`)
- `remote` (скачивание через прокси, указанный в `PROXY_REMOTE`)

Поведение правил:

- Приоритет секций фиксирован: `direct` проверяется первым, затем `local`, затем `remote`.
- Поддерживаются точные совпадения хостов (например, `youtube.com`).
- Поддерживаются wildcard-хосты вида `*.` (например, `*.youtube.com`).
- `*` можно использовать как глобальный fallback для всех остальных доменов.
- Правило с суффиксом `!` получает наивысший приоритет над обычными правилами внутри своей секции и даже перекрывает общие настройки других секций.

### Пример

```yaml
routing:
  direct:
    - "*.ru"
    - "vk.com"

  local:
    - "*.youtube.com"
    - "*.youtu.be"

  remote:
    - "*"
```
